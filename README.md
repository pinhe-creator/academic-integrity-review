# 学术诚信核查 · Academic Integrity Review

一个面向公众的研究诚信核查工具：输入一篇论文的 **DOI**，或上传论文 **PDF**、**数据表（Excel/CSV）** 与**代码**，
它会从公开来源检索、并对文件本身做轻量取证，把所有**值得人工核对的线索**逐条列出，每条都标明**来源**与**当前状态**。

> **它只呈现证据，不下结论。** 不输出“造假概率”、不做任何指控——判断权完全交给你。

# 模块一 · 如何运行

想在自己电脑上把它跑起来，按下面步骤即可。**完全不懂编程也能照做。** Windows 与 macOS 分别看对应小节。

## 准备：安装 Python（只需一次）

打开 <https://www.python.org/downloads/>，下载并安装 **Python 3.10 或更高版本**。

- **Windows 用户**：安装第一屏请务必勾选 **“Add Python to PATH”**，再点 Install。
- **macOS 用户**：官网下载安装即可；或用 Homebrew：`brew install python`。

## 获取代码

在本仓库点 **Code → Download ZIP** 下载并解压；或用 `git clone <仓库地址>`。
记住解压后的文件夹位置（里面应有 `app.py` 这个文件）。

## Windows 运行步骤

1. 打开解压后的文件夹，在空白处**按住 Shift + 鼠标右键** → “在此处打开 PowerShell 窗口”。
2. 在弹出的窗口里**逐行**输入下面命令（每行按一次回车）：
   ```powershell
   python -m venv .venv
   .venv\Scripts\activate
   pip install -r requirements.txt
   uvicorn app:app
   ```
3. 看到 `Uvicorn running on http://127.0.0.1:8000` 后，打开浏览器访问 **http://127.0.0.1:8000**。
4. 想停止：回到窗口按 **Ctrl + C**。

> 若提示 “python 不是内部或外部命令”，说明安装时没勾 “Add Python to PATH”，重装一次并勾上即可。

## macOS 运行步骤

1. 打开“终端”（Terminal）。输入 `cd ` 后，把文件夹拖进终端窗口（会自动补全路径），回车进入该文件夹。
2. **逐行**输入：
   ```bash
   python3 -m venv .venv
   source .venv/bin/activate
   pip install -r requirements.txt
   uvicorn app:app
   ```
3. 看到 `Uvicorn running on http://127.0.0.1:8000` 后，打开浏览器访问 **http://127.0.0.1:8000**。
4. 想停止：按 **Control + C**。

> macOS 只有 `python3`、没有 `python`，第一行务必用 `python3`。激活成功后命令行最前面会出现 `(.venv)`。

## 之后再次运行

进入文件夹后，只需**激活环境再启动**（依赖不必重装）：

- Windows：`.venv\Scripts\activate` ，然后 `uvicorn app:app`
- macOS：`source .venv/bin/activate` ，然后 `uvicorn app:app`

依赖较多（含数据与图像处理库），首次 `pip install` 需要几分钟，属正常现象。

# 模块二 · 这个工具能做什么

工具有两类入口：**DOI**（去公开数据库查）和**上传文件**（对内容做取证）。
下面逐项说明每个功能的**作用、原理与局限**。请务必读完局限——**没有任何一项检测是确定的**。

## 1. 撤稿 / 勘误 / 关注声明查询

- **作用**：输入 DOI，查这篇论文是否被撤稿、更正，或被发布过“关注声明”，并标明当前状态。
- **原理**：调用 Crossref（已整合 Retraction Watch 撤稿数据库），查找指向该论文的更新记录。这些是出版方的正式动作，属事实陈述。
- **局限**：只覆盖**已被正式记录**的撤稿/勘误；尚未被记录、或仍在调查中的问题查不到；依赖 DOI 填写正确。

## 2. 开放获取全文自动获取

- **作用**：输入 DOI，自动寻找并下载论文的开放获取（OA）全文 PDF，供后续文本与图像检测——你只给一个 DOI 也能跑全套分析。
- **原理**：调用 Unpaywall（覆盖数万家出版商与机构仓储），获取合法的开放获取全文链接。
- **局限**：付费墙论文通常没有 OA 版本（需手动上传 PDF）；部分只提供网页落地页而非 PDF 直链，无法自动下载。

## 3. 同行评议讨论（PubPeer）

- **作用**：指向该论文在 PubPeer 上的公开讨论；自动检索功能即将上线。
- **原理**：PubPeer 是发表后同行评议平台，许多数据与图像问题最早在此被同行公开指出。
- **局限**：自动检索依赖官方接口（即将上线）；目前提供前往 PubPeer 的手动检索入口。

## 4. 数据统计取证（Excel / CSV）

对上传的数值表做几项稳健的统计检验。**所有结果都只是“线索”，绝不是结论。**

### 4a. 末位数字分布
- **作用**：检查某数值列小数点后某一位的数字是否异常偏离均匀分布。
- **原理**：真实测量数据的末位数字通常接近均匀；若某个**非 0 数字**异常占多数，可能是人为编造（卡方检验 + 效应量门槛）。
- **局限**：当占多数的是**数字 0** 时**不报**——因为计算机无法区分 `0.4` 与 `0.40`，“某位是 0”多半只是精度/舍入造成的假象；此外，全是同一个值的列、含大量零的列也不检测。

### 4b. 近似等差序列
- **作用**：检查某列是否“按原始行序、每行以近乎恒定的步长递增或递减”。
- **原理**：真实测量极少出现这种规律；它常见于“由公式生成”的伪造数据（例如 `94.755, 101.977, 109.2…`，相邻差恒为约 7.22）。
- **局限**：
  - **太不规整的近似等差抓不到**：若相邻差的波动超过阈值、序列不足约 5 个点、或取值为整数（被当作时间/剂量等坐标轴而排除），都不会报。
  - **有些等差 / 线性序列是正常机理造成的**：例如两个变量本身线性相关、标准曲线、或人为设定的等距输入（剂量梯度、采样时间点）。这些会被标出，但**并不代表造假**，必须结合上下文人工判断。

### 4c. 整行重复
- **作用**：检查是否存在多行数值内容完全相同。
- **原理**：整块数据完全重复在真实记录中少见，可能是复制粘贴。
- **局限**：只识别**完全相同**的行；被轻微改动过的近似重复抓不到。

## 5. 图像重复检测（PDF）

- **作用**：在论文 PDF 中找出高度相似或重复的图片，并给出两图缩略图供人工对比，精确到第几页第几张。
- **原理**：提取内嵌图片，按内容去重、跳过透明度蒙版、过滤近乎纯色的图，再用感知哈希（dHash）比较整体相似度；并区分“同一张图跨页复用”与“相似但不完全相同的两张”。
- **局限**：
  - **只能发现“整张图高度相似”的情况；经过处理的图片基本检不出**——例如裁剪、旋转、缩放、调色、翻转，以及**局部拼接 / 把一张图的一部分复制到另一处**（这恰恰是许多真实造假的手法）。
  - 这是基础启发式，准确度**远不及** ImageTwin、Proofig 等专业图像取证工具。
  - 同一图的相关子图有时会被标为相似，需人工看缩略图甄别。

## 6. 文本可疑模式（PDF / 代码 / 文本）

- **作用**：扫描文本中未删除的 AI 生成痕迹与“扭曲术语”。
- **原理**：匹配大模型常见用语（如 “as an AI language model…”）和洗稿工具把标准术语替换成的怪异近义词（如把 signal-to-noise 写成 “flag to clamor”，是论文工厂的典型指纹）。
- **局限**：只能抓到**未经编辑的明显痕迹**，稍作改写即检不出；内置词典有限；**本工具绝不运行上传的代码**，因此代码与论文结论是否一致仍需人工尝试复现。

## 贯穿始终的原则与共同局限

- 工具**只汇集公开信号与统计现象，逐条标注来源与状态**；呈现 ≠ 指控。“命中某条规则”绝不等于“存在学术不端”。
- 所有自动检测都**既会漏报、也会误报**：伪造得足够巧妙就抓不到（漏报），正常数据也可能触发规则（误报）。
- 撤稿、勘误是出版方的正式记录；匿名评论、统计与图像观察则只是**提示性线索**，分量不同。
- **最终判断必须由人完成**：查阅原始来源、查看作者回应、必要时尝试复现。

## 使用统计 / Usage stats

页脚展示「访问次数」与「已核查次数」（也可访问 `/stats` 查看原始数字）。后端**自动二选一**：

- **默认（本地文件）**：记录在 `stats.json`，路径可用环境变量 `STATS_FILE` 修改。适合本地开发；
  但免费 PaaS 文件系统是临时的，**重启 / 重新部署会清零**。
- **Upstash Redis（推荐线上用，外部存储，跨重启累计）**：设置以下两个环境变量后**自动启用，代码无需改动**：
  - `UPSTASH_REDIS_REST_URL`
  - `UPSTASH_REDIS_REST_TOKEN`

  申请步骤：到 <https://upstash.com> 注册 → 新建一个 Redis 数据库（区域选离你服务器近的）→
  在数据库页面的 **REST API** 区复制上面两个值 → 填进平台的环境变量 → 重新部署。计数从此跨重启 / 重新部署累计。
  （计数用 Redis 的 `INCR`，天然原子，多人同时访问也不会数错。）

**本地运行也会计数**：默认写入本机的 `stats.json`，但这与线上是**两套、各算各的**。
若想让本地的每次「打开 / 核查」也上报到线上**同一个**中央计数器，把 `.env.example` 复制为 `.env`，
填入与线上**相同**的 `UPSTASH_REDIS_REST_URL` 与 `UPSTASH_REDIS_REST_TOKEN` 即可——本地启动会自动加载 `.env`。
`.env` 含密钥、已被 `.gitignore` 排除，**请勿提交或分发**。
